# Commit Pressure Is Not Publication Authority

## Governance Problem

A growing set of local changes can create pressure to consolidate quickly. That
pressure is operationally real, but it does not decide whether the content is
safe to publish.

## Boundary Principle

Commit readiness and publication readiness are separate judgments. A clean
commit group may still contain material that needs human review, stronger
abstraction, or private-only handling.

## Practical Risk

When pressure to reduce clutter becomes authority to publish, review quality
can degrade. The workflow may reward closure instead of safety.

## Safe Practice

Treat commit pressure as a signal to organize, not as permission to release.
Separate public notes, private work, generated artifacts, and review-required
material before any commit decision.

## Review Prompt

Before committing public knowledge, ask:

- Is this content public by design?
- Has it been abstracted enough?
- Does it belong in exactly one public repository?
- Would publication expose more than the lesson?
